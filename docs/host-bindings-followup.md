# Host Bindings — Follow-up Work

This document tracks deferred work after PR1–PR4 of the host-binding feature
(vault key ⇄ SSH host pattern mapping that solves the OpenSSH `MaxAuthTries=6`
problem).

The four shipped PRs cover the full functional path: data model, sync hook,
CLI surface, and a graphical bind-hosts dialog with process-peek host
inference. Everything below is **post-MVP polish** — none of it blocks the
feature from being usable.

Implementation progress:

- Done: user documentation (#4), design ADR (#5), quoted `Include` / `IdentityFile` paths (#6.2), Unix SSH config permissions (#6.5), catch-all warnings (#6.3), and debug logging for process-peek inference failures (#3).
- Explicitly deferred: system tray / menu-bar entry (#1).
- Remaining: Linux/macOS validation, large-list profiling, concurrent edit locking, and broader integration tests.

**Why:** GUI users currently have to either (a) trigger the bind dialog

Neither is great for users who never open a shell.

**Scope:**

  `tray-icon`; macOS: NSStatusItem; Linux: AppIndicator/`tray-icon`).
- Menu items:
  - `Open bindings…` → sends the existing `bind-hosts-dialog` control command
  - `Lock` / `Sync` / `Status` → reuse current control commands
  - `Quit`
- Show a small indicator when the vault is locked.

**Touchpoints:**

**Open questions:**

- On Linux, AppIndicator support is desktop-dependent — fall back to no tray
  gracefully.

## 2. Virtual scrolling / large key lists in `BindHostsDialog`

**Why:** The current Slint dialog uses `ListView` which already virtualizes,
but the *host list* uses an in-page `for...in` inside a `ListView` and the key
list renders all entries up front when the model is built. Users with 50+
vault keys may see slow first-paint.

**Scope:**

- Profile dialog open time with a synthetic 200-key vault.
- If problematic: lazy-build the `VecModel<KeyEntry>` in chunks via
  `slint::Timer`, or switch to a search/filter LineEdit at the top of the key
  pane.
- Consider adding a "Show only bound keys" toggle.

**Touchpoints:**

- `crates/sshwarden-ui/src/bind_hosts/slint_dialog.rs`

## 3. Linux / macOS `sysinfo` cmdline permissions

**Why:** PR4 added `get_peer_cmd(pid)` for SSH-target inference. On Windows
this generally works because the daemon and the SSH client run as the same
user. On Linux, reading `/proc/<pid>/cmdline` is permitted same-uid by
default, but containerized scenarios (Flatpak, snap, Docker) or hardened
kernels (`kernel.yama.ptrace_scope`, AppArmor) may deny access. On macOS,
`sysinfo` uses `proc_pidinfo` which can return truncated cmdline on newer OS
versions.

**Scope:**

- Test on:
  - bare Linux (Ubuntu 24.04 default, with and without `ptrace_scope=1`)
  - Linux inside Flatpak/snap (sshwarden could be packaged either way)
  - macOS 14+ where SIP affects process introspection
- When `get_peer_cmd` returns `None`, the bind dialog falls back to empty
  prefill — verify the UX message is acceptable (currently silent).
- Debug logging for inference failures is implemented; Linux/macOS validation remains.

**Touchpoints:**

- `crates/sshwarden-agent/src/peerinfo/gather.rs`
- `src/main.rs::infer_ssh_target_from_pid`

## 4. User documentation — done

**Why:** This feature has a non-trivial mental model (managed snippet, Include
line, portable mode interactions). Users need a single page they can read.

**Scope (suggested outline):**

1. **Problem** — `MaxAuthTries=6` and why having many vault keys breaks SSH.
2. **How sshwarden solves it** — per-host `IdentityFile` + `IdentitiesOnly`,
   generated by sshwarden.
3. **Quickstart** —
   ```bash
   sshwarden ssh-config install     # one-time
   sshwarden bindings add github-key github.com
   ssh github.com                   # just works
   ```
4. **GUI path** — first sign request → `Bind & Approve…` → done.
5. **File layout** — what gets written where (portable vs non-portable).
6. **Uninstalling** — `sshwarden ssh-config uninstall`, what's left behind.
7. **Troubleshooting** —
   - "Include line missing" → run `ssh-config install`
   - "Wrong key offered" → check `sshwarden ssh-config show`
   - "Bind dialog shows no prefill" → cmdline read failed; explain when

Implemented in `docs/host-bindings.md`, linked from `README.md`, and reflected in `ROADMAP.md`.

## 5. ADR for the design — done

Implemented in `docs/adr/0023-host-bindings-and-managed-ssh-config.md`.

**Original suggested ADR content:**

- Why local-only `bindings.json` instead of stuffing into Bitwarden vault item
  metadata (avoids backend schema dependency; allows offline use).
- Why we generate `~/.ssh/sshwarden_config` and inject `Include` rather than
  filtering at `REQUEST_IDENTITIES` time (protocol-level limitation: agent
  doesn't know target host until sign request).
- Why we keep the snippet outside `config_dir()` in portable mode (OpenSSH
  client only reads from fixed paths, so `~/.ssh/config` Include line is
  unavoidable; we document the one-line footprint).
- Why "Bind & Approve" is one click (UX: avoid double-prompting the user).
- Why process-peek inference is best-effort (silently falls back).

## 6. Edge cases worth a once-over

These are not bugs per se — flag them during a real-world soak.

- **Multiple `Include` lines:** if a user manually adds another `Include` to
  `~/.ssh/config` before/after the sshwarden block, `remove_sshwarden_include_line`
  should still target only ours. Confirmed by code review; worth a manual test.
- **Snippet file path with spaces / non-ASCII:** fixed for both `Include` and
  `IdentityFile`; status/uninstall also accept legacy unquoted Include lines.
- **Binding to `*` or other catch-all patterns:** warning added in CLI and GUI.
- **Concurrent edits:** two `sshwarden bindings add` invocations racing. The
  tmp-rename atomic save in `bindings.rs` prevents corruption but the second
  writer's read can lose the first writer's add (read-modify-write race).
  Add a file lock (`fs2::FileExt::try_lock_exclusive`) if this becomes a
  real-world problem.
- **`~/.ssh` permissions on Unix:** fixed for SSHWarden-created `~/.ssh`,
  `~/.ssh/config`, and `~/.ssh/sshwarden_config` paths.

Currently we have unit tests for:

- `bindings.rs` — 9 tests on the data model

What's missing: an end-to-end test that goes

read the generated sshwarden_config → assert content`.

**Suggested location:** `crates/sshwarden-config/tests/bindings_integration.rs`
or a new `tests/` directory at the workspace root. Should use a temp dir via
`SSHWARDEN_HOME` env to avoid touching the user's real config_dir.
