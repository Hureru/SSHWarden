# Notification hub URL resolution

SSHWarden will treat an explicitly configured notification URL as either a notification-service base URL or a complete hub URL: values ending in `/hub` or `/anonymous-hub` are recognized as complete hub URLs, while other values have `/hub` appended after converting the scheme to WebSocket. When no notification URL is configured, official Bitwarden hosts are mapped explicitly (`vault.bitwarden.com` to `notifications.bitwarden.com`, `vault.bitwarden.eu` to `notifications.bitwarden.eu`), and all other server URLs are treated as self-hosted by appending `/notifications`, which supports Vaultwarden and Bitwarden-compatible deployments such as a Cloudflare Durable Object wrapper at `/notifications/hub`. SSHWarden's baseline runtime uses the authenticated `/hub` for SSH key sync and logout notifications; `anonymous-hub` is recognized only to avoid mis-parsing explicit URLs and is not used for baseline SSH agent behavior.
